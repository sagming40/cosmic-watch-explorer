## 1. 설계의 출발점
 
### 1.1 이 서비스에는 사진이 없다
 
설계를 시작하기 전에 반드시 짚어야 할 제약이 하나 있다.
 
**NASA NeoWs API는 소행성 사진을 제공하지 않는다. NASA Exoplanet Archive도 외계행성 사진을 제공하지 않는다.**
 
우리가 다루는 데이터는 전부 **숫자와 분류값**이다. 직경 추정 범위, 접근 거리, 상대 속도, 이심률, 분광형. 흔히 떠올리는 "우주 사진이 가득한 웹사이트"는 이 프로젝트의 데이터로는 애초에 만들 수 없다.
 
그래서 이 서비스의 정체성은 **우주 화보집이 아니라 관측 계기판**이다. 참고할 대상은 NASA/JPL Horizons 시스템이나 천문대 관제 화면이지, 우주 배경화면 사이트가 아니다.
 
이 판단이 이후의 모든 디자인 결정을 규정한다.
 
### 1.2 사용자가 실제로 알고 싶은 것
 
일반 사용자가 소행성 데이터를 볼 때 궁금한 건 하나다.
 
> **"그래서 이게 위험한 거야, 아니야?"**
 
`miss_distance_km = 4,821,033`이라는 숫자는 이 질문에 답하지 못한다. 482만 km가 가까운 건지 먼 건지 일반인은 감이 없다.
 
그래서 이 서비스는 **모든 거리를 달까지의 거리(384,400km)를 기준으로 환산해서 함께 보여준다.** "12.5 LD(달 거리)"라고 하면 "달보다 12배 넘게 멀구나"가 즉시 이해된다. 이건 NASA와 천문학계도 실제로 쓰는 표현 방식(Lunar Distance)이다.
 
이 원칙이 이 서비스의 **핵심 차별점**이자 시그니처가 된다.

## 2. 디자인 토큰
 
### 2.1 컬러 팔레트
 
천문대 관제실은 **적색 조명**을 쓴다. 어두운 곳에 적응한 눈(암순응)이 흰 빛에 노출되면 다시 적응하는 데 20분 이상 걸리기 때문이다. 이 서비스의 색은 그 환경에서 가져온다.
 
| 토큰 | HEX | 용도 |
|---|---|---|
| `--ink` | `#0B0E14` | 페이지 배경 (푸른기 도는 검정) |
| `--panel` | `#161B26` | 카드·패널 배경 |
| `--line` | `#252C3B` | 구분선, 테두리 |
| `--bone` | `#E6E4DE` | 본문 텍스트 |
| `--dim` | `#7A8296` | 보조 텍스트, 라벨 |
| `--sodium` | `#E8A33D` | 주요 강조색 (나트륨등 호박색) |
| `--hazard` | `#D64545` | 위험 소행성 표시 **전용** |
 
#### 왜 이 색인가
 
- **`--sodium`**: 도시 야간 조명(나트륨등)의 색. 천문 관측을 방해하는 광공해의 상징적인 색이면서, 동시에 어두운 배경에서 눈이 가장 편하게 인식하는 파장대다. 흔히 쓰이는 네온 시안 대신 이 색을 쓴다.
- **`--hazard`**: **오직 잠재적 위험 소행성(PHA) 표시에만** 사용한다. 버튼, 링크, 어디에도 쓰지 않는다. 이 색이 화면에 보이면 그건 무조건 위험 플래그라는 규칙을 지킨다. 색이 의미를 갖게 만드는 방법은 그 색을 아껴 쓰는 것뿐이다.
### 2.2 타이포그래피
 
| 역할 | 서체 | 용도 |
|---|---|---|
| 디스플레이 | IBM Plex Sans Condensed (600) | 페이지 제목, 큰 수치 |
| 본문 | IBM Plex Sans (400/500) | 설명, 라벨, 버튼 |
| 데이터 | **IBM Plex Mono (400)** | 모든 수치, 좌표, ID |
 
#### 수치에 고정폭 서체를 쓰는 이유
 
이 서비스의 화면은 대부분 **숫자가 세로로 나열된 표**다. 일반 서체는 글자마다 폭이 달라서 자릿수가 어긋난다.
 
```
일반 서체              고정폭 서체
1,234,567 km          1,234,567 km
891,022 km              891,022 km      ← 자릿수가 맞아떨어짐
12,405,881 km        12,405,881 km
```
 
고정폭이면 **숫자를 읽지 않고 길이만 봐도** 자릿수 차이가 보인다. 장식이 아니라 기능이다.
 
### 2.3 타입 스케일
 
| 단계 | 크기 | 용도 |
|---|---|---|
| `display` | 40px / 700 | 상세 페이지 천체명 |
| `h1` | 28px / 600 | 페이지 제목 |
| `h2` | 20px / 600 | 섹션 제목 |
| `body` | 15px / 400 | 본문 |
| `data` | 15px / Mono | 수치 |
| `label` | 12px / 500 / letter-spacing 0.08em / 대문자 | 필드 라벨 |
 
### 2.4 레이아웃
 
- 최대 폭 **1280px**, 중앙 정렬
- 기본 간격 단위 **8px** (8 / 16 / 24 / 40 / 64)
- 카드 모서리 반경 **4px** — 계기판의 성격에 맞게 최소한만
- 그림자 사용하지 않음. 깊이는 배경 명도 차이(`--ink` → `--panel`)로만 표현

## 3. 시그니처 요소 — 달 거리 스케일 바
 
이 서비스가 기억될 단 하나의 요소.
 
모든 NEO의 접근 거리를 **달의 궤도를 고정 기준선으로 삼은 공통 스케일** 위에 표시한다.
 
```text
        지구                    달 궤도                         
         │                        │                            
    ┌────┼────────────────────────┼──────────────────────────┐
    │    ▓                        │                          │   0.6 LD  ⚠
    │    │        ▓               │                          │   3.2 LD
    │    │                        │      ▓                   │  18.7 LD
    │    │                        │                    ▓     │  41.0 LD
    └────┴────────────────────────┴──────────────────────────┘
         0                      1 LD                       50 LD
                          (384,400 km)
```
 
- 가로축은 **로그 스케일**을 쓴다. 접근 거리가 0.5 LD부터 100 LD까지 200배 차이가 나기 때문에, 선형 축으로는 가까운 것들이 전부 왼쪽 끝에 뭉친다.
- **1 LD 지점에 고정 기준선**을 긋는다. 이 선보다 왼쪽에 있으면 달보다 가까이 온 것이다.
- 1 LD 안쪽으로 들어온 천체만 `--hazard` 색으로 표시한다.
이 하나의 그래픽이 "482만 km"라는 무의미한 숫자를 "달보다 12배 먼 거리"라는 직관으로 바꿔준다.
 
> **구현 메모**: 별도 라이브러리 없이 CSS `flex` + `position: absolute`로 충분히 만들 수 있다. `Math.log10()`으로 위치를 계산하면 된다.

## 4. 화면 목록 및 라우팅
 
| # | 경로 | 화면명 | 인증 |
|---|---|---|---|
| 1 | `/` | NEO 대시보드 (홈) | 불필요 |
| 2 | `/neo/:id` | NEO 상세 | 불필요 |
| 3 | `/exoplanets` | 외계행성 카탈로그 | 불필요 |
| 4 | `/exoplanets/:id` | 외계행성 상세 | 불필요 |
| 5 | `/compare` | 크기 비교 | 불필요 |
| 6 | `/login` | 로그인 | 불필요 |
| 7 | `/signup` | 회원가입 | 불필요 |
| 8 | `/watchlist` | 내 관심 천체 | **필요** |
 
### 4.1 홈과 대시보드를 합친 이유
 
별도의 랜딩 페이지를 만들지 않는다. 접속하면 **오늘 날짜의 NEO 대시보드가 바로 나온다.**
 
MVP에서 "우리 서비스는 이런 걸 합니다" 소개 페이지는 개발 비용만 쓰고 사용자를 한 번 더 클릭하게 만든다. 데이터를 바로 보여주는 게 이 서비스의 목적에 맞다.
 
### 4.2 화면 흐름도
 
```text
                        ┌─────────────┐
                        │      /      │
                        │ NEO 대시보드 │ ←── 접속 시 진입점
                        └──────┬──────┘
                               │ 목록 항목 클릭
                               ▼
                        ┌─────────────┐
                        │  /neo/:id   │
                        │  NEO 상세   │
                        └──────┬──────┘
                               │ "크기 비교" 클릭
                               ▼
        ┌──────────────► ┌─────────────┐ ◄──────────────┐
        │                │  /compare   │                │
        │                │  크기 비교  │                │
        │                └─────────────┘                │
        │                                               │
 ┌──────┴───────┐                              ┌────────┴────────┐
 │ /exoplanets  │ ──── 항목 클릭 ────────────► │/exoplanets/:id  │
 │   카탈로그   │                              │  외계행성 상세  │
 └──────────────┘                              └─────────────────┘
 
 
  [Watchlist 버튼 클릭 시]
        │
        ├── 로그인 상태 ────► 즉시 등록 / 해제 (페이지 이동 없음)
        │
        └── 비로그인 ───────► /login?next=현재경로
                                    │
                              로그인 성공
                                    │
                                    ▼
                          원래 있던 페이지로 복귀
```
 
### 4.3 비로그인 상태에서 Watchlist를 누르면
 
사용자가 소행성 상세 페이지를 한참 보다가 "저장" 버튼을 눌렀는데 로그인 페이지로 튕기고, 로그인 후 홈으로 돌아가버리면 — 보던 페이지를 다시 찾아가야 한다.
 
**해결: `?next=` 파라미터로 원래 위치를 기억한다.**
 
```text
/neo/2357621 에서 저장 클릭
        ↓
/login?next=/neo/2357621 로 이동
        ↓
로그인 성공
        ↓
/neo/2357621 로 복귀
```

## 5. 사용자 시나리오
 
### 시나리오 1 — 오늘 위험한 소행성이 있는지 확인 (비회원)
 
**사용자**: 뉴스에서 소행성 접근 기사를 보고 검색해서 들어온 사람
 
| 단계 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1 | 사이트 접속 | 오늘 날짜의 NEO 목록을 자동 조회해 표시 |
| 2 | — | 상단에 요약: "오늘 접근 6건 / 위험 분류 1건 / 최근접 0.8 LD" |
| 3 | 스케일 바에서 왼쪽 끝 항목 확인 | 1 LD 안쪽 항목이 `--hazard` 색으로 강조됨 |
| 4 | 해당 항목 클릭 | NEO 상세 페이지로 이동 |
| 5 | 직경·속도·궤도 확인 | 추정 직경을 "455m ~ 1,018m" 범위로 표시 |
 
**성공 조건**: 접속 3초 안에 "오늘 위험한 게 있나 없나"를 판단할 수 있다.
 
---
 
### 시나리오 2 — 지구와 비슷한 외계행성 찾기 (비회원)
 
**사용자**: 지구형 행성이 궁금한 사람
 
| 단계 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1 | 카탈로그 메뉴 진입 | 전체 목록 1페이지 + 필터 패널 표시 |
| 2 | 반지름 `0.8 ~ 1.5` (지구 대비) 입력 | — |
| 3 | 거리 `100광년 이하` 입력 | 내부적으로 파섹으로 환산해 조회 |
| 4 | 검색 실행 | 조건에 맞는 결과 + 총 건수 표시 |
| 5 | 결과 항목 클릭 | 상세 페이지: 행성 정보 + 모항성 정보 |
| 6 | "지구와 크기 비교" 클릭 | 비교 페이지로 해당 행성이 선택된 상태로 이동 |
 
**성공 조건**: 조건을 걸었을 때 왜 그 결과가 나왔는지 화면에 남아 있다. (적용된 필터를 칩 형태로 계속 표시)
 
---
 
### 시나리오 3 — 회원가입 후 관심 천체 저장
 
| 단계 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1 | NEO 상세에서 "저장" 클릭 | 비로그인 → `/login?next=/neo/2357621` |
| 2 | "계정 만들기" 클릭 | `/signup?next=/neo/2357621` |
| 3 | 아이디·이메일·비밀번호 입력 | 유효성 실시간 검사 |
| 4 | 가입 완료 | 자동 로그인 후 원래 페이지로 복귀 |
| 5 | "저장" 다시 클릭 | 버튼이 "저장됨"으로 즉시 전환 |
 
**성공 조건**: 가입 후 사용자가 길을 잃지 않고 원래 하려던 행동을 마친다.
 
---
 
### 시나리오 4 — 저장한 천체 다시 보기 (회원)
 
| 단계 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1 | 상단 메뉴에서 "내 관심 천체" | 소행성 / 외계행성 탭 구분 표시 |
| 2 | 소행성 탭 | 저장한 NEO 목록 + 각각의 다음 접근 예정일 |
| 3 | 항목의 삭제 버튼 | 확인 없이 즉시 삭제 + "실행 취소" 5초 노출 |
 
> **삭제 확인창을 띄우지 않는 이유**: 북마크 해제는 되돌리기 쉬운 저위험 동작이다. 확인창은 위험한 동작(계정 삭제 등)에만 쓴다. 대신 실행 취소를 제공한다.

## 6. 화면별 설계
 
### 6.1 NEO 대시보드 (`/`)
 
```text
┌────────────────────────────────────────────────────────────────┐
│  COSMIC WATCH          소행성   외계행성   크기비교      로그인 │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  지구 근접 소행성                          ◄  2026-08-21  ►    │
│  ────────────────────────────────────────────────────────────  │
│                                                                │
│   접근 건수        위험 분류         최근접 거리                │
│      6               1              0.8 LD                     │
│                                    307,520 km                  │
│                                                                │
├────────────────────────────────────────────────────────────────┤
│  접근 거리 분포                                                 │
│                          │ 달 궤도                             │
│   ┌──────────────────────┼───────────────────────────────┐     │
│   │   ▓                  │      ▓        ▓      ▓    ▓   │     │
│   └──────────────────────┴───────────────────────────────┘     │
│   0.1 LD              1 LD            10 LD          100 LD    │
├────────────────────────────────────────────────────────────────┤
│  정렬:  [거리 ▼]  [속도]  [크기]                                │
│                                                                │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ ⚠ 2024 PT5                                    0.80 LD    │  │
│  │   추정 직경  8 ~ 18 m        상대속도  9.42 km/s         │  │
│  ├──────────────────────────────────────────────────────────┤  │
│  │   357621 (2005 EG94)                         12.53 LD    │  │
│  │   추정 직경  455 ~ 1,018 m   상대속도  18.83 km/s        │  │
│  ├──────────────────────────────────────────────────────────┤  │
│  │   (2019 QK4)                                 41.02 LD    │  │
│  │   추정 직경  120 ~ 268 m     상대속도  11.07 km/s        │  │
│  └──────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────┘
```
 
#### 설계 결정
 
- **날짜 이동은 좌우 화살표 + 날짜 클릭 시 달력.** 날짜 입력 필드를 직접 타이핑하게 만들지 않는다. 사용자는 대부분 "어제/오늘/내일"만 본다.
- **거리를 LD와 km 두 가지로 병기.** LD는 직관, km은 정확성. 목록에서는 LD를 크게, km을 작게.
- **위험 소행성만 `⚠` + `--hazard`.** 안전한 항목에는 아무 색 표시도 하지 않는다. 초록색 "안전" 배지를 달면 화면 전체가 배지밭이 된다.
#### 차트를 무엇으로 그릴 것인가
 
요구사항 4.1의 "차트 시각화"를 구체화한다. 두 개를 만든다.
 
1. **달 거리 스케일 바** (위 시그니처) — 직접 구현
2. **거리-속도 산점도** — `Recharts` 사용
산점도 설계:
 
| 축 / 속성 | 데이터 |
|---|---|
| X축 | 접근 거리 (LD, 로그 스케일) |
| Y축 | 상대 속도 (km/s) |
| 점 크기 | 추정 직경 (최댓값 기준) |
| 점 색상 | 위험 여부 |
 
**하나의 차트에 4개 변수**를 담는다. 막대그래프 두 개를 나란히 놓는 것보다 정보 밀도가 높고, "가깝고 빠르고 큰 것"이 어디 있는지 한눈에 보인다.
 
> Recharts를 고르는 이유: React 컴포넌트로 되어 있어 JSX 안에서 `<ScatterChart>` 처럼 쓰면 된다. D3는 강력하지만 직접 SVG를 다뤄야 해서 지금 단계에서는 시간이 더 든다.

```text
│ └────────────────────┘                                        │
└────────────────────────────────────────────────────────────────┘
```
 
#### 설계 결정
 
- **적용된 조건을 칩으로 계속 표시한다.** 필터 패널의 입력 필드는 스크롤하면 안 보인다. 결과를 보면서 "내가 무슨 조건을 걸었더라"를 다시 확인하러 올라가게 만들면 안 된다. 칩의 `×`로 개별 해제도 가능하다.
- **거리는 광년으로 입력받는다.** DB에는 파섹으로 저장되어 있지만 사용자에게 파섹을 요구하지 않는다. 변환은 백엔드가 한다.
- **검색 조건은 URL 쿼리스트링에 반영한다.** `?radius_min=0.8&radius_max=1.5&distance_max=100` 형태. 이렇게 하면 검색 결과를 그대로 공유하거나 북마크할 수 있고, 뒤로가기가 자연스럽게 동작한다.
- **값이 없는 항목은 `—` 로 표시.** `0`이나 `없음`이라고 쓰지 않는다. NASA가 측정하지 못한 것과 값이 0인 것은 다르다.

### 6.4 크기 비교 (`/compare`)
 
```text
┌────────────────────────────────────────────────────────────────┐
│  크기 비교                                                      │
│  ────────────────────────────────────────────────────────────  │
│                                                                │
│  비교 대상  [ + 소행성 추가 ]  [ + 외계행성 추가 ]              │
│                                                                │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │                                                          │  │
│  │              ⬤                    ○           ·         │  │
│  │                                                          │  │
│  │          TRAPPIST-1 e           지구      357621         │  │
│  │          반지름 0.92           기준       455~1,018 m    │  │
│  │                                                          │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                │
│  ⓘ 소행성은 정확한 직경이 알려지지 않아 추정 범위로            │
│    표시됩니다. 바깥 원이 최댓값, 안쪽 원이 최솟값입니다.       │
└────────────────────────────────────────────────────────────────┘
```
 
#### 설계 결정
 
- **지구는 항상 화면에 있다.** 지우거나 뺄 수 없는 고정 기준이다. 기준이 없으면 크기 비교는 의미가 없다.
- **소행성은 이중 원으로 그린다.** 최소/최대 추정 직경을 각각 원으로 그려서, 불확실성 자체를 시각화한다. 평균값 하나로 뭉개는 것은 데이터 왜곡이다.
- **스케일 문제**: 지구 반지름은 6,371km, 소행성은 0.5km 수준이다. 실제 비율로 그리면 소행성이 **화면상 한 픽셀도 안 된다.** 따라서 아래 규칙을 쓴다.
  - 소행성끼리는 서로 실제 비율로 비교
  - 지구·외계행성끼리는 서로 실제 비율로 비교
  - 두 그룹 사이는 **로그 스케일**로 배치하고, "실제 비율이 아님"을 화면에 명시
> 이 한계를 숨기지 않고 안내 문구로 밝히는 것이 정직한 처리다.

## 7. 상태별 화면 (빈 화면 / 로딩 / 오류)
 
데이터를 외부 API에 의존하는 서비스에서 이 세 가지는 예외가 아니라 **일상**이다.
 
### 7.1 빈 결과
 
| 상황 | 화면 문구 | 함께 제공할 것 |
|---|---|---|
| 해당 날짜에 NEO 0건 | "2026-08-21에는 지구에 접근하는 소행성이 없습니다." | 다른 날짜로 이동하는 버튼 |
| 검색 결과 0건 | "조건에 맞는 외계행성이 없습니다." | 어떤 조건을 완화하면 되는지 힌트 + 조건 지우기 |
| Watchlist 비어 있음 | "저장한 천체가 없습니다." | 소행성 목록 / 외계행성 목록으로 가는 링크 |
 
**빈 화면은 막다른 길이 아니라 다음 행동을 안내하는 자리다.** "결과 없음"만 띄우고 끝내지 않는다.
 
### 7.2 로딩
 
NASA API를 처음 호출하는 날짜는 응답이 느릴 수 있다(수 초).
 
- 목록 영역에 **스켈레톤**(회색 자리표시자)을 띄운다. 스피너 하나만 돌리면 화면이 비어 보인다.
- 3초를 넘기면 "NASA에서 데이터를 가져오는 중입니다" 문구를 추가한다. 왜 기다리는지 알려주면 체감 대기 시간이 줄어든다.
### 7.3 오류
 
| 상황 | 문구 | 동작 |
|---|---|---|
| NASA API 장애 | "NASA 데이터 서버에 연결할 수 없습니다. 저장된 데이터를 표시합니다." | DB에 있는 데이터로 대체 표시 |
| 요청 한도 초과 | "잠시 후 다시 시도해 주세요." | 재시도 버튼 |
| 로그인 필요 | (오류 아님) | `/login?next=` 로 이동 |
 
> **오류 문구는 사과하지 않는다.** "죄송합니다"로 시작하는 대신 **무슨 일이 일어났고 지금 무엇을 할 수 있는지**를 알린다.

## 8. 반응형
 
| 구간 | 폭 | 주요 변화 |
|---|---|---|
| 데스크톱 | 1024px 이상 | 기준 레이아웃 |
| 태블릿 | 768 ~ 1023px | 카탈로그 필터 패널이 상단 접이식으로 이동 |
| 모바일 | 767px 이하 | 목록 카드가 1열, 표는 가로 스크롤, 스케일 바는 세로 방향 |
 
모바일에서 **표를 카드로 바꾸지 않는다.** 궤도 정보처럼 항목이 많은 표는 가로 스크롤이 오히려 읽기 쉽다. 억지로 카드로 쪼개면 값끼리 비교가 안 된다.

## 9. 접근성 기준
 
- 모든 색 대비는 **WCAG AA(4.5:1)** 이상. `--dim`(#7A8296)을 `--ink` 배경에서 쓸 때 특히 확인할 것.
- **위험 여부를 색으로만 표시하지 않는다.** `⚠` 아이콘과 "잠재적 위험 소행성"이라는 텍스트를 함께 쓴다. 적록색약 사용자를 위해서다.
- 키보드 `Tab` 이동 시 포커스 링이 보여야 한다. `outline: none`을 쓰지 않는다.
- 차트에는 대체 텍스트 또는 동일 데이터의 표를 제공한다.
- `prefers-reduced-motion` 설정을 존중한다.

## 11. 개발 순서 제안
 
UI를 한 번에 다 만들지 않는다. **데이터가 화면까지 도달하는 경로를 먼저 하나 뚫는다.**
 
```text
1단계  NEO 대시보드 목록 (차트 없이, 표만)
         → Django API ↔ React 통신이 되는지 확인
2단계  NEO 상세
         → 라우팅과 상세 조회 확인
3단계  LunarDistanceBar
         → 시그니처 요소. 여기서 서비스의 인상이 결정된다
4단계  외계행성 카탈로그 + 검색
         → 백엔드 핵심 기능(다중 조건 검색)
5단계  로그인 / 회원가입
6단계  Watchlist
7단계  크기 비교
8단계  산점도 차트
9단계  빈 화면 / 오류 / 로딩 상태 정리
10단계 반응형 + 접근성 점검
```
 
> 9단계를 마지막이 아니라 **각 단계마다 조금씩** 해두는 것이 낫다. 몰아서 하면 반드시 빠뜨린다.
