# 0007. 브랜치 · PR 없이 main 하나로

- 상태: 확정
- 날짜: 2026-10-27

## 맥락

M0 ~ M3 중반은 마일스톤 브랜치 + PR 방식이었다. 회사 PC · 집 PC · 노트북을 오가는 1인 작업이라 브랜치 동기화 비용이 PR 기록의 이점보다 커졌고, 9/16에는 push 안 한 작업이 유실됐다.

## 결정

모든 작업은 `main`에서 하고 PR을 만들지 않는다. 히스토리 재작성은 사용자가 요청할 때만 한다. 규칙은 CLAUDE.md 1.1절.

## 검토한 대안

- **마일스톤 브랜치 + Draft PR 유지**: 무엇을 검증하고 병합했는지 기록이 남지만, 기기를 옮길 때마다 브랜치를 맞춰야 한다.

## 감수할 것

미완성 코드도 `main`에 올라간다. 세션이 끊길 것 같으면 `wip:` 커밋으로 push한다.
