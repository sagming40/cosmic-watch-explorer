## 1. 이 문서의 사용법

### 1.1 소요 기간은 잠정치다

처음 쓸 때의 추정이고 DEVLOG 실측으로 계속 보정한다. 밀렸다는 사실 자체는 문제가 아니다. **밀린 것을 모르는 채로 진행하는 것**이 문제다.

### 1.2 상태 표기

⬜ 시작 전 / 🔄 진행 중 / ✅ 완료 (완료 기준 전부 충족). 하위 체크박스가 일부만 채워진 상태에서 상위 마일스톤을 ✅로 바꾸지 않는다.

### 1.3 완료 기준은 "속을 수 없는 형태"로 쓴다

"동작함" 대신 판정 가능한 문장만 쓴다. 예: "계정 2개로 각각 저장한 뒤 교차 로그인하면 서로의 항목이 보이지 않는다".

      - **핵심 질문은 "한국에서 보이나"** ─ 일식은 지구의 좁은 띠에서만 보여서 날짜만 있으면 반쪽짜리다("있다"와 "여기서 보인다"는 다르다). 월식은 밤인 쪽 절반에서 다 보인다 → 한국이 그때 밤인지만 보면 된다
      - 데이터 출처 후보 (10-28 직접 호출해 본 결과): **USNO 천문 API** `aa.usno.navy.mil/api/eclipses/solar/year` ─ 일식 연도 목록 정상(2027: 2월 6일 금환일식·8월 2일 개기일식). 같은 곳 **월식 연도 목록은 404**, 지역별 일식 정보(`solar/date`)는 500 → 월식·"한국에서 보이나"는 다른 출처가 필요. 후보: NASA GSFC 일식·월식 표(Espenak, 정적 표 ─ `fetch_exoplanets`처럼 한 번 받아 DB에 저장)
      - **원칙 예외 허용** (10-28 사용자 결정: "원칙은 지키라고 있지만 진행 상황 따라 유연하게") ─ REQUIREMENTS 3.2절 "자체 궤도 계산 엔진 제외"는 그대로 두되, 이 기능의 **"한국에서 보이나" 계산은 공개 출처에 없으면 직접 계산해도 된다**(Skyfield 같은 천문 계산 라이브러리 + NASA/JPL 행성 위치표). 순서: ① 공개 기관 표를 먼저 찾고 ② 없으면 직접 계산 ③ 직접 계산한 값은 반드시 공개 자료(NASA 표·한국천문연구원 천문 현상 안내 등)와 몇 건 대조해 맞는지 확인한 뒤 쓴다
      - 착수 때 정할 것: 메뉴 이름, 보여 줄 기간(앞으로 몇 년), 지난 일식·월식도 보일지, "한국" 기준 지점(서울 한 곳 vs 지역 선택)

**완료 기준**

- [ ] 7일 안에 접근하는 소행성을 저장하면 배지가 1, 해제하면 0

## 12. 범위 관리

### 12.1 새 기능이 떠올랐을 때

**구현하지 않는다.** [REQUIREMENTS](REQUIREMENTS.md) 3.2절 표에 항목만 추가한다. 못 끝낸 것은 대개 핵심 기능이다. 예쁜 것부터 만들고 싶어지기 때문이다.

### 12.2 일정이 밀렸을 때 자르는 순서

우선순위는 [REQUIREMENTS](REQUIREMENTS.md) 6장을 따른다. **L → S 순서로 자르고, M은 자르지 않는다.** 자른 항목은 지우지 말고 이유와 함께 DEVLOG `[설계]`에 남긴다.

### 12.3 마일스톤 간 작업 이관

M3에 있던 작업을 M4에서 했다면, 원래 위치에는 체크박스 대신 인용구 각주만 남긴다. 완료 여부의 출처는 **항상 한 곳**이어야 한다. 두 군데 체크박스가 있으면 한쪽이 반드시 거짓말이 된다.
